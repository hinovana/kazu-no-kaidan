# 6×6 原本基準・難易度監査

## 位置づけ

この監査は、v3.4の6×6生成問題から人間レビュー対象を絞るための補助資料である。
児童の正答率、所要時間、誤答過程を測った難易度校正ではない。

原本6×6は、10・12・14端点のprofileごとに1問しかない。そのため、原本問題を
難易度分布として扱わず、一つの基準点として生成1,000問/profileの中での位置を
測る。

## 入力と再現方法

- 原本: `ref/onaji-no-tsunagi-source-corpus.json`の二重照合済み6×6問題3問
- 生成: 10・12・14端点を各1,000問、合計3,000問
- 比較対象: 同じ端点multiplicityを持つ原本問題と生成問題
- 原本座標: ローカル参照JSONからだけ読み込み、公開fixtureや生成seedへ利用しない

リポジトリルートで次を実行する。

```bash
npm run audit:onaji-no-tsunagi:6x6-difficulty -- \
  --reference-corpus ../ref/onaji-no-tsunagi-source-corpus.json \
  --samples-per-profile 1000 \
  --review-samples 5 \
  --output-prefix /private/tmp/onaji-no-tsunagi-v34-difficulty-audit
```

指定したprefixへJSON集計と自己完結HTMLを出力する。HTMLは、問題を先に見てから
答えと指標を開き、人間の判断とメモを入力できる。入力はbrowser内へ保存され、
「レビュー結果をJSON保存」から書き出せる。生成物とレビュー入力はGit管理対象に
しない。

一つのprofileだけを監査する場合は`--profile`を指定する。

```bash
npm run audit:onaji-no-tsunagi:6x6-difficulty -- \
  --reference-corpus ../ref/onaji-no-tsunagi-source-corpus.json \
  --profile 6x6-4-4-4 \
  --samples-per-profile 1000 \
  --output-prefix /private/tmp/onaji-no-tsunagi-v34-6x6-4-4-4-audit
```

`--profile`は生成後の収集filterではなく、最初から指定profileだけを生成する。
したがって、生成request数は`--samples-per-profile`と一致する。

`6x6-4-4-2`の端点配置仮説を対照評価する場合は、次を実行する。

```bash
npm run audit:onaji-no-tsunagi:6x6-terminal-placement -- \
  --reference-corpus ../ref/onaji-no-tsunagi-source-corpus.json \
  --samples-per-cohort 1000 \
  --review-samples 5 \
  --output-prefix /private/tmp/onaji-no-tsunagi-v34-terminal-placement
```

同じlevel 2 seed系列から、生成探索へ組み込んだ6条件を通過した問題を基準に、
中央端点数3〜5、端点で埋まる2×2、中央外周境界、外周一辺集中型を含む
下記10条件の集計を行う。HTMLには完成盤面の条件別却下率と、生成探索枝・
記号割当てに対する剪定率を別表で表示する。

## 比較指標

| 指標 | 難しい側として扱う方向 | 注意 |
| --- | --- | --- |
| 初期選択肢量 | 多い | pairing候補数と、各端点の局所出口数の積 |
| 強制出口 | 少ない | 人が実際にその端点から始める証拠ではない |
| solver状態数 | 多い | solver固有の探索量であり、人の思考量ではない |
| canonical solutionの総曲がり | 多い | 見た目の複雑さの代理であり、難易度そのものではない |

初期選択肢量とsolver状態数は原本の0.5倍〜2倍、強制出口は±1、総曲がりは±2を
原本近傍とする。

- `原本近傍`: 4指標のうち3つ以上が近傍
- `明らかに簡単側`: 2指標以上が簡単方向で、難しい方向の指標がない
- `明らかに難しい側`: 2指標以上が難しい方向で、簡単方向の指標がない
- `指標混合`: 簡単方向と難しい方向が併存する

この閾値は人間レビュー候補を絞るために設計した保守的な規則である。
`v3.4-draft.3`では、人間レビュー済みの`6x6-4-4-2`に限り、
`明らかに簡単側`を除外する採用gateにも利用する。他profileでは合否に使わない。

## 原本基準点

3問はいずれも、現行ルールとsolverでpairingを含む`exact: 1`だった。

| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| `6x6-4-4-2` | 2 | 124,416 | 1 | 1,628 | 2,242 | 8 | 33 |
| `6x6-4-4-4` | 2 | 26,873,856 | 0 | 126 | 169 | 4 | 31 |

使用マス数を難易度の単調な指標として分類には使わない。

## 6x6-4-4-2の端点配置仮説

次の10条件を、原本と生成問題から導かれる検証可能な仮説として評価する。

1. 外周を除いた中央4×4に、○・△・□を各1個以上置く
2. 中央4×4の端点は合計3〜5個とする
3. 中央4×4内で上下左右に隣接する端点pairは、記号を問わず1組までとする
4. 外周で上下左右に隣接する端点pairは1組までとする
5. 外周で隣接する場合は異なる記号同士だけを許容し、同じ記号同士は禁止する
6. 盤面全体で縦・横に3個以上連続する端点を却下する
7. 端点で4マスすべてが埋まる2×2を却下する
8. 2×2のうち3マスが端点で埋まるL字型の3連を却下する
9. 中央4×4と外周の境界をまたいで上下左右に隣接する端点pairは2組までとする
10. 同じ外周辺に接し、その辺と直交する隣接端点pairが3組以上ある
    外周一辺集中型の配置を却下する

原本`6x6-4-4-2`は10条件を満たす。中央には各記号1個、合計3端点があり、
中央内の隣接は0組である。外周には7端点があり、最下段左端の○と右隣の□が
隣接するため、外周隣接は異記号の1組である。縦横3連と2×2はなく、
L字3連もない。中央4×4と外周の境界をまたぐ隣接は0組であり、
同一辺に集中する直交隣接pairは3組未満である。

最初の対照実験では、中央の記号網羅と外周隣接制限を組み合わせた群を
各1,000問評価した。

上記200問は、配置条件を生成探索へ組み込む前の比較基準である。
人間レビュー後、v3.4-draft.2では次の6条件を
`6x6-4-4-2`の生成policyへ組み込んだ。

- 中央4×4に各記号1個以上
- 中央隣接は最大1pair
- 外周隣接は最大1pair
- 外周の同記号隣接を禁止
- 縦3連・横3連を禁止
- L字型3連を禁止

最初の4条件のうち記号に依存しない条件と縦横3連は経路探索中に枝刈りし、
L字型3連は完成coverで探索へ戻す。記号網羅と外周同記号隣接は、完成coverへ
試す15通りの記号割当てから不適合な割当てを除外する。禁止配置は完成
`Puzzle`またはsolver入力へ渡さない。

中央端点数3〜5、端点で埋まる2×2、中央外周境界の隣接2pairまで、
外周一辺集中型3pairの禁止は、`v3.4-draft.2`では監査条件だった。
`v3.4-draft.3`では10端点の後段採用filterへ移した。同じ条件は端点密度の高い
12・14端点には適用していない。

最初の1,000問を生成policy通過群、10条件をすべて満たす1,000問を最終群として
比較した。生成policyの6条件に対する完成盤面の違反は0問だった。最終10条件の
通過率は92.4%であり、組み込み前の5.3%から大幅に改善した。

## v3.4-draft.3の採用選別

選別の制御構造は全profileで共通化し、profile設定にfilter条件、原本基準点、
連続棄却上限を持たせる。当面は`6x6-4-4-2`だけを有効化し、5×5、12端点、
14端点はfilter条件が空、原本基準点が`null`のため出力選択へ影響しない。

10端点は、一意性・最適性・既存機械gateまで完了した一候補に対して次の順で
選別する。

1. 生成探索へ未導入だった4配置条件をすべて確認する
2. 原本基準の4指標で候補を分類する
3. `明らかに簡単側`なら一問だけ再生成する
4. それ以外は、フォームで選択された`原本近傍`、
   `明らかに難しい側`、`指標混合`だけを採用する

分類済み候補が10問連続で`明らかに簡単側`なら、部分的なWorksheetを返さず
request全体をerrorにする。error reportには10候補の盤面、解、seed、topology、
分類指標と配置filter結果を含める。WorkerはreportをUIへ返し、通常画面は
console logとJSON downloadを提供する。

この選別は「明らかに簡単な粗悪候補を減らす」ための工学的gateである。
`原本近傍`、`明らかに難しい側`、`指標混合`のいずれも、それだけで良問や
児童向け適正を意味しない。

## 解釈とv3.4昇格判断

- 機械指標が一貫して原本より難しい問題は、3,000問中0問だった。
- 10端点と14端点では、原本より初期選択肢量が少なく、強制出口が多い問題が
  多いため、簡単側候補の割合が高い。
- 12端点では、原本より初期選択肢量が大幅に少ない一方、生成問題の総曲がりと
  solver探索量は大きいことが多く、95.8%が指標混合になった。
- 「簡単側候補が多い」ことだけを理由に不合格にはしない。取っ掛かりが明瞭でも、
  pairing選択やその後の経路探索に十分な手応えがある可能性は人間が確認する。

監査HTMLは、簡単側、原本近傍、混合指標の両端を優先し、足りない場合は分布全体
